# Few-Shot Examples

Use these examples to stabilize phrasing, structure, and coverage style.

## Example 1: Requirement To Test Points

### Input

用户管理模块支持新增用户、编辑用户、启用/停用用户，用户可绑定角色。角色变更后应立即影响页面操作权限。

### Preferred Output Shape

```markdown
## 可测试性问题
- [如无则省略]

## 覆盖模型
- 模块：用户列表、新增用户、编辑用户、状态切换、角色绑定、权限生效
- 维度：角色 x 操作 x 状态
- 功能点拆解：用户基础操作、用户状态流转、角色绑定、权限即时生效
- 功能点关系：角色绑定 -> 权限生效，用户状态 -> 登录/关键操作限制

## 测试点清单
| 模块 | 测试点 | 类型 | 优先级 | 来源方法 |
|------|--------|------|--------|----------|
| 用户新增 | 必填字段校验 | 功能/异常 | P1 | EP |
| 用户新增 | 唯一账号重复校验 | 功能/异常 | P1 | EP |
| 用户状态 | 停用后禁止登录或关键操作 | 状态 | P0 | ST |
| 角色绑定 | 角色变更后立即影响按钮权限 | 权限/状态 | P0 | ST |
| 权限控制 | 前端隐藏但后端仍拒绝越权调用 | 权限 | P0 | EG |
```

## Example 2: Requirement To Detailed Cases

### Input

根据“角色删除时若仍被用户引用则不允许删除”生成测试用例，输出默认格式。

### Preferred Output Shape

```markdown
| Case ID | Module | Requirement ID | Title | Preconditions | Steps | Expected Results | Priority | Test Type |
|---------|--------|----------------|-------|---------------|-------|------------------|----------|-----------|
| TC-0001 | 角色管理 / 删除 | [待确认] | 删除被引用角色时系统阻止删除 | 已存在角色A，且用户U绑定角色A | 1. 打开角色列表 2. 选择角色A 3. 点击删除 | 1. 弹出删除确认 2. 确认删除后系统提示“角色已被引用，无法删除” 3. 角色A仍存在 | P0 | 权限/异常 |
```

## Example 3: Existing Case Review

### Input

评审这组角色管理用例是否完整。

### Preferred Output Shape

```markdown
## Findings

### Blocking
- 缺少“被引用角色不可删除”用例，存在关键业务规则漏测。
- 已有删除用例未区分“前端按钮可见性”和“后端越权拦截”，权限测试目标混杂。

### Important
- 多条用例预期结果写成“删除成功”“提示正确”，不可验证。
- 未覆盖角色变更后对已绑定用户权限即时生效场景。

### Suggestion
- 为每条用例增加关联需求ID和设计方法标签。
```

## Example 4: AI Artifact Review

### Input

检查一份 AI 生成的测试用例文档是否可直接用于执行。

### Preferred Output Shape

```markdown
## AI 产物评审

- 结论：可作为草稿，不建议直接执行

| 风险类别 | 结论 | 说明 |
|----------|------|------|
| 事实性 | 有风险 | 若干字段名与原需求不一致 |
| 逻辑性 | 有风险 | 同时声称“删除成功”和“被引用不可删除” |
| 指令遵循 | 基本符合 | 输出结构完整 |
| 结构完整 | 部分缺失 | 缺少关联需求与优先级 |
| 重复冗余 | 有 | 3 条用例验证目标相同 |
```

## Example 5: Risk Summary

### Preferred Output Shape

```markdown
## 质量风险摘要

- 范围：用户管理、角色管理
- 总体判断：核心流程已覆盖，但权限边界和引用删除风险仍需重点复核
- 高风险模块：角色删除、角色绑定、生效时机
- 已验证关键风险：角色列表展示、基本新增编辑
- 未验证关键风险：越权接口拦截、角色变更后的历史会话影响
- 建议动作：补充权限后端拦截和状态一致性用例后再评估发布
```
