# Figma / 设计稿阅读

当需求文档里带设计稿链接（Figma 等），或需要「设计稿 vs 需求」逐项核对时，读这个文件。

设计稿不是补充材料，是证据来源：需求文档通常只写指标口径，**空状态、分档状态、备用视图、视觉规则、命名**往往只存在于设计稿与设计评论里。

## 一、先判断能不能匿名访问（不要直接开浏览器）

- 用 curl 探测设计文件链接与 og:image / thumbnail 接口：thumbnail 返回 404、embed 页出现权限校验文案 ⇒ 该文件不可匿名访问，必须用带登录态的浏览器
- 需要登录时，只能使用用户真实浏览器配置的副本（其登录态）；**任何情况下都不要索取或输入账号密码**
- Hermes：`browser.use_real_profile` 要求真实 Chrome **完全退出**——关窗口不等于退出。先核对 `pgrep -f "Google Chrome" | wc -l` 为 0、profile 的 SingletonLock 已释放，再发起浏览器调用
- Hermes 浏览器默认无头。无头 UA（`HeadlessChrome`）+ `navigator.webdriver=true` 会触发 Figma 的 CloudFront 403「Request blocked」：用 `Network.setUserAgentOverride` 覆盖为普通 Chrome UA 并带 acceptLanguage，再 reload（用 `document.title` 确认进入文件）
- 权限边界要写进结论：只读文件会出现「You can only view and comment on this file」⇒ 不要尝试编辑/导出；Dev Mode 可能被拦截（「We've sent a reminder about your Dev Mode request」）⇒ 退回放大截图方案，不要宣称拿到了设计参数

## 二、读取设计内容

- **画布文字不在 DOM 里**：`document.body.innerText` 只能拿到界面外壳（页面名、图层名、评论、属性面板）。设计稿里的文案/数值/表头一律要靠放大截图 + 视觉识别
- 图层树走无障碍树：`cdp('Accessibility.getFullAXTree')['nodes']` 过滤 `role == 'row'` 可拿到 Pages / Layers 行，用 `DOM.getBoxModel` 换算出点击坐标
- **DOM 节点 id 会变**（切换模式、面板滚动后重新渲染）：每次都用当前 AX 树按**图层名**重新匹配，绝不复用上一轮的 id
- 在图层面板里选中某个 Frame 会自动展开其子级 ⇒ 用「选中 → 看子级 → 再选中」逐层下钻到模块级；行长距离滚动时用鼠标滚轮在面板 x 位置滚动，再重新取 box
- 截图前先把窗口调大（`Browser.getWindowForTarget` → `Browser.setWindowBounds`，例如 1760x1100），否则小窗口里字不可读
- 缩放：`Shift+1` 缩放到适应、`Shift+2` 缩放到选中对象；逐模块放大用 **⌘/Ctrl（modifiers=4）+ 滚轮 deltaY=-120 约 ×1.27/步**，以光标为中心；反向 +120 同次数即可复原。当前缩放比例从工具栏百分比取
- 平移用**无修饰键滚轮**（deltaX/deltaY）；注意左右两侧面板不是画布，光标落在面板上滚轮无效（这是最容易踩的坑：目标模块被面板遮住时怎么滚都没反应，先把光标移进画布区）
- 截图助手通常固定输出同一个文件路径，每张图拍完立刻复制成「模块名.png」，否则互相覆盖
- 每张截图交给本机的视觉能力读取，并**要求极简输出**（例如「只列文字清单，不解释」），否则一次识别就能吃掉大量上下文

## 三、证据纪律

- 每张截图记录：文件页名 + Frame 名 + 缩放比例 + 提取时间，便于复核
- **设计评论是规格的一部分**：评论里常写视觉规则（颜色条件、悬停行为、字段折行规则），但需求文档没有。按评论编号引用为证据（例：评论 #49 定义圆圈颜色条件）
- **状态/变体帧是最有价值的素材**：空状态帧（各模块空态文案与占位符）、分档状态帧、备用视图帧（世界地图/多语言）通常能直接补上需求缺失的空态与边界覆盖
- 不能核到的就不要写：下拉选项未展开时不要猜；视觉模型可能报错图片像素尺寸，坐标换算以相对比例为准，并用 `file` / `sips` 核实际尺寸
- 只读权限下无法导出节点数据，结论要写明「基于放大截图的视觉识别」

## 四、差异如何落到用例里

- 在用例工作簿里新增独立页 **设计差异**，列建议：`序号 / 差异类别 / 差异点 / 需求(wiki)口径 / 设计稿口径 / 影响用例ID / 对用例的处理建议 / 证据 / 状态`
- **需求文本始终是断言基线**：
  - 设计稿补充、需求没写 → 新增用例（并标注来源为设计稿）
  - 设计稿与需求冲突 → 用例预期保留需求口径，写明「设计稿为 X，需求为 Y，按产品定稿执行，差异记录缺陷」，状态置 `待确认`
  - 绝不为迁就设计稿而静默改写预期结果
- 逐条差异都要能回指证据（Frame 名 / 截图 / 评论编号），并在评审建议里同步需要产品拍板的高优先项

## 五、写回工作簿的技术要点

- 向已生成的 xlsx 追加页/行时，直接改 `xl/worksheets/sheetN.xml` 更稳：同时更新 `<dimension>` 与 `<autoFilter>` 的 ref，并补 `[Content_Types].xml`、`xl/workbook.xml`、`xl/_rels/workbook.xml.rels` 三处登记，其余页保持字节不变（避免丢样式、数据校验、条件格式）
- 表头必须落在第 1 行；把旧行合并进同一个 sheet 时，新行的 `r` 属性要与实际行号一致，否则会出现「表头在第 2 行」「旧行被覆盖」这类静默错误
- 改写完成后用表格库回读校验：页签名、行数、表头、关键单元格、乱码与 zip 完整性都要过一遍
